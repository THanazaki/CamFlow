### 全体の約束

- 全テーブルに RLS を有効にし、本人（`auth.uid() = user_id`）の行だけを読み書きできる
- 主キーはすべて uuid（`sync_tombstones` / `audit_logs` は連番）。端末で採番してからサーバに送る
- `updated_at` はサーバの書き込みで `set_updated_at()` が必ず上書きする。競合はサーバに後から届いた書き込みが勝つ
- 物理削除は `record_tombstone()` が `sync_tombstones` に記録し、端末に伝える
- すべての操作は `record_audit_log()` が `audit_logs` に記録する。**テーブルを足したらこのトリガも付ける**
- 撮影回数などの集計値はカラムで持たず、ビューから導出する
- 端末側（IndexedDB / Dexie）は `sync_tombstones` と `audit_logs` 以外の11テーブルを同じ形でミラーし、各行に `_dirty`（未送信フラグ）を足して持つ

**データは2系統に分かれる。** 「過去の撮影」を扱う画面は、片方だけを見ると数が合わなくなる。

| 系統 | テーブル | 入口の画面 |
|---|---|---|
| 運用フロー | `sessions` / `slots` / `slot_models` | 予約情報入力 → 確定撮影情報入力 → 確定撮影情報 |
| 遡及登録 | `shoot_history` / `shoot_history_models` | 過去撮影登録 |
