# デプロイ手順（Supabase の接続設定）

デプロイ先で新規アカウントを作ろうとして
「**Supabase の接続情報が設定されていません**」と出たときの直し方。

## 原因

新規登録とログインは `/api/auth`（`src/app/api/auth/route.ts`）を通して Supabase にアカウントを作る。
このとき環境変数 `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を読むが、
デプロイ先にこの2つが設定されていないとエラーになる。

`test` / `test` のテストアカウントだけは Supabase を使わないため、設定がなくてもログインできる
（データはその端末だけに残り、同期されない）。

## 直し方

### 1. Supabase のクラウドプロジェクトを作る

1. https://supabase.com で New project を作る
2. Project Settings → API で次の2つを控える
   - Project URL（`https://<project-ref>.supabase.co`）
   - anon（public）key

### 2. テーブルを作る

`supabase/migrations/` の SQL を**ファイル名の順に**適用する。次のどちらかの方法を使う。

- **SQL Editor に貼り付けて実行する**: Supabase の SQL Editor で、`20261103000100_init_enums.sql` から順に実行する
- **Supabase CLI を使う**（Docker のあるホストで実行する。このコンテナには Docker が無い）:
  ```bash
  supabase link --project-ref <project-ref>
  supabase db push
  ```

この手順を省くと、登録はできても同期でエラーになる。

`supabase/seed.sql` はローカル開発用のダミーデータなので、**本番には入れない**。

### 3. デプロイ先に環境変数を設定する

Vercel の場合は Settings → Environment Variables で設定する。

```
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
```

### 4. デプロイし直す

`NEXT_PUBLIC_` で始まる値は**ビルド時に埋め込まれる**。環境変数を保存しただけでは反映されないので、
Redeploy する。

### 5. 確認メールの設定（任意）

Supabase は初期設定のままだと、登録後に届く確認メールのリンクを押すまでログインできない。

- すぐ使いたいとき: Authentication → Providers → Email の「Confirm email」をオフにする
- オンのまま使うとき: Authentication → URL Configuration の Site URL をデプロイ先の URL にする
  （そうしないと確認メールのリンクが `localhost` を指す）

## 手元（開発環境）で試す場合

同じ2つの値を `.env.local` に書いて、開発サーバーを再起動する（`.env.example` 参照）。

## 関連する設定

| 環境変数 | 内容 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase の接続先（必須） |
| `NEXT_PUBLIC_DISABLE_TEST_ACCOUNT=true` | テストアカウント（test / test）を無効にする。設定したらビルドし直す |
| `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` / `RECAPTCHA_SECRET_KEY` | reCAPTCHA のキー。今は一時的に外している（`src/lib/auth/recaptcha.ts`） |
